# 학습 계획 — my-music-app

> Phase/마일스톤별로 "무엇을 알아야 하는지"와 "이미 아는지"를 정리한다.
> 원칙: 아직 설명 안 한 개념을 전제로 묻지 않는다. 쉬운 것(이미 아는 것) → 이름 붙이기 → 새 개념 순으로 간다.

## Phase 1 — 이미 다른 프로젝트에서 써본 것들

다음은 study-quiz·uvm-drill·PQO·vocab-app 등에서 이미 실전으로 써본 개념이다. 마일스톤 진행 중 "그때 그거 맞다" 정도로만 짚고 넘어간다.

| 개념 | 어디서 이미 씀 | Phase 1에서 쓰는 곳 |
|---|---|---|
| JSON으로 데이터 모델링 | study-quiz(퀴즈 90문항), PQO(content.js) | 1.1, 1.3 |
| 바닐라 JS로 DOM 렌더링 (리스트·필터) | study-quiz, uvm-drill | 1.4 |
| localStorage로 상태 저장 | study-quiz(Daily Quiz), PQO(체크리스트 진도) | 1.5 |
| git add(경로 지정)·commit·push | 모든 프로젝트 | 1.8 |
| GitHub Pages 배포 | study-quiz, uvm-drill, PQO | 1.8 |

## Phase 1 — 이번에 새로 정리해볼 것

| 개념 | 왜 새로운가 | 체크 질문 |
|---|---|---|
| 의도 태그 (내 취향 vs 탐구용) 설계 | 지금까지 앱은 "정답/오답" 같은 단일 축이었는데, 이번엔 "왜 이걸 담았는가"라는 축이 하나 더 생긴다 | 스키마 설계 후: 한국 아티스트 엔트리와 아이들 노래 엔트리를 같은 필드로 표현하면 뭐가 문제인지 스스로 설명할 수 있는가 |
| 규칙 기반 추천을 코드로 표현하기 | 이전 프로젝트는 저장/조회 위주였고, "여러 태그를 점수로 환산해 순위를 매기는" 로직은 처음 | 코드를 보고 왜 이 곡이 1등으로 나왔는지 태그 점수로 설명할 수 있는가 |

## Phase 1.5 — 진짜 새로운 영역 (AI 연결)

이 구간은 Nick의 기존 프로젝트 어디에도 없던 것이다. 여기서는 마일스톤을 잘게 쪼개고, 각 개념을 먼저 설명한 뒤에만 체크 질문을 던진다. Phase 1을 끝낸 시점에 마일스톤을 구체화하면서 이 표도 채운다. 지금 예상되는 개념만 미리 적어둔다(확정 아님).

- 서버리스 함수란 무엇이고 왜 필요한가 — API 키를 클라이언트 코드에 그대로 넣으면 안 되는 이유부터.
- 프런트엔드 ↔ 백엔드 ↔ 외부 API(Claude) 요청이 오가는 흐름.
- 무료 티어의 실제 한도와 개인 사용 기준 예상 비용.

## Phase 2, 3 — 착수 시점에 채운다
디자인(Phase 2)과 APK 패키징(Phase 3)의 학습 체크포인트는 각 Phase 착수 세션에서 구체화한다. 지금 미리 정하면 실제 상황과 어긋날 가능성이 크다.
