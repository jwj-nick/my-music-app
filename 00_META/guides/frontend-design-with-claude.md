# 가이드 — Claude와 프론트엔드 디자인 작업하기

> Nick 요청(2026-08-23): "이후에 클로드 디자인, 프론트엔드 디자인 스킬 등을 사용해보는 가이드".
> Phase 2.5 리뷰나 이후 디자인 반복에서 실제로 쓸 수 있는 방법들.

## 1. 이 프로젝트에서 이미 쓰고 있는 것

- **아티팩트 프리뷰 루프**: 코드 수정 → `build_preview.js` → 아티팩트 재발행(같은 URL) →
  폰/PC에서 즉시 확인. 디자인 반복의 기본 루프. 아티팩트는 뷰어의 라이트/다크 테마를 따라
  렌더되므로 두 테마 검증에도 좋다.
- **디자인 SSOT 문서** (`design_plan.md`): 토큰·타이포·컨셉을 문서로 못박고 코드가 따라간다.
  Claude에게 "design_plan.md 기준으로 X를 고쳐줘"라고 하면 일관성이 유지된다.
- **artifact-design 스킬**: Claude Code가 아티팩트를 만들 때 자동으로 로드되는 내장 스킬 —
  로드맵 아티팩트의 토큰 시스템·3단 테마 가드가 이 스킬의 규칙대로 만들어졌다.
  별도 호출 불필요, 아티팩트 생성 요청이면 자동 적용된다.

## 2. 디자인 반복에서 Claude에게 잘 시키는 법

- **스크린샷을 붙여라**: 폰 스크린샷을 대화에 첨부하고 "여기서 카드 간격이 답답함" 식으로
  말하면 텍스트 설명보다 훨씬 정확히 전달된다. Claude는 이미지를 읽을 수 있다.
- **형용사보다 참조**: "더 세련되게" 대신 "Apple Music의 카드 밀도처럼" / "로드맵 아티팩트의
  콜아웃처럼" — 구체적 참조가 결과를 좌우한다.
- **한 번에 한 축**: 색·간격·타이포를 한 문장에 다 시키면 뭉개진다. "이번엔 간격만" 식으로.
- **왜를 물어라**: "왜 앰버를 골랐어?" — 학습 목표(Phase 2)가 디자인 이해라면, 결정의 근거를
  묻는 게 코드 받아쓰기보다 남는 게 많다. design_plan.md의 각 결정에는 이유가 붙어 있다.

## 3. Chrome 연동 (claude-in-chrome)

Claude Code가 Chrome 탭을 직접 열고 스크린샷을 찍을 수 있다 (이 세션에서도 사용).
디자인 검증에 쓰는 법: "라이브 사이트 열어서 다크 모드 스크린샷 찍어서 보여줘" —
Nick이 직접 안 봐도 Claude가 시각 확인 후 문제를 보고할 수 있다.
단, 확장 연결 상태에 따라 캡처가 타임아웃 나는 경우가 있음(이 세션에서 겪음) —
그럴 땐 Nick이 스크린샷을 찍어 붙이는 쪽이 빠르다.

## 4. 관련 학습 자원 (Nick의 기존 자산과 연결)

- **50_APP_Study**: SW 생태계 학습 트랙에 "CSS 아키텍처(토큰/캐스케이드)" 주제를 추가할 가치가
  있다 — 이 앱의 style.css가 실전 교재가 된다.
- **study-quiz 패턴**: 디자인 개념(특이성, 캐스케이드, 컨테이너 쿼리 등)을 `/quiz-publish`로
  퀴즈화해서 복습하는 것도 기존 파이프라인 재사용.
- CSS 공부 순서 제안 (이 앱 기준): ① 토큰과 3단 테마 가드(teaching 노트 §4) →
  ② flex/grid와 gap(카드 레이아웃) → ③ 특이성과 캐스케이드(왜 토큰만 쓰는가) →
  ④ 모션과 reduced-motion → ⑤ 반응형(현재 max-width 640 단일 컬럼의 한계).
