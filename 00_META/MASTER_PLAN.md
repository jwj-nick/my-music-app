# MASTER_PLAN — my-music-app

> ⭐ 진도 SSOT. Phase 전환·범위 변경은 반드시 이 파일에서 갱신한다.
> 학습 체크포인트(무엇을 알아야 하는지, 이미 아는지)는 `learning_plan.md`에 따로 관리한다.

## 현재 위치
**Phase 1 — 마일스톤 1.7(청취 로그) 확인 대기** (1.1~1.6 완료, 2026-08-22)

## 작업 방식 — 학습 우선
이 프로젝트는 결과물만큼 "만드는 과정을 완전히 이해하는 것"이 목표다. 자율진행(Claude가 알아서 빠르게 다 만드는 것)을 쓰지 않는다. 마일스톤마다 아래 순서를 지킨다.

1. **개념 설명** — 이번 마일스톤에서 새로 쓰는 개념을 먼저 설명한다. 이미 아는 것(다른 프로젝트에서 써본 것)은 짧게 확인만 하고 넘어간다.
2. **함께 구현** — 코드를 같이 짜거나, Claude가 짠 걸 Nick이 줄 단위로 읽고 이해한다.
3. **확인** — `learning_plan.md`의 체크 질문에 답하거나, 직접 브라우저/폰에서 눈으로 동작을 확인한다.
4. **통과 후 다음 마일스톤** — 확인이 끝나야 다음 마일스톤으로 넘어간다. 급하게 건너뛰지 않는다.

## Phase 계획
| Phase | 내용 | 상태 |
|---|---|---|
| 0 | 방향 확정 — 재생 소스(Q01)·취향 데이터 유무(Q02)·폰/데스크톱 우선순위(Q03) | ✅ |
| 1 | 기능 기초 — 데이터 모델, 정적 뼈대 앱, 인앱 입력, 규칙 기반 추천, 청취 로그, 첫 GitHub Pages 공개 배포 | 🔄 진행 중 |
| 1.5 | AI 연결 — 폰에서 즉석으로 취향을 탐구·확장하는 기능. 서버리스 백엔드 최초 도입 | ⏳ Phase 1 이후 구체화 |
| 2 | 디자인 심화 — 앨범아트 그리드·타이포그래피·모션·다크/라이트 테마·클래식/아이돌 별도 탭(Q06). 포트폴리오급 UI | ⏳ Phase 1.5 이후 |
| 3 | APK 패키징 — 실제 안드로이드 폰에 설치해 쓰는 최종 형태 | ⏳ Phase 1 직후 러프 1차, Phase 2 직후 최종 2차 |

**Phase 순서를 이렇게 잡은 이유:** 기능(1) → AI(1.5) → 디자인(2) 순서인 건, 껍데기(디자인)를 입히기 전에 알맹이(기능)가 먼저 확실히 동작해야 하기 때문이다. AI 연결(1.5)을 디자인보다 먼저 둔 이유는, 서버리스 백엔드 추가처럼 구조가 더 크게 바뀌는 쪽을 먼저 안정시키고 나서 그 위에 디자인을 입혀야 나중에 다시 손대는 일이 줄기 때문이다. 이 순서는 Phase 1을 끝내고 실제로 되짚어보면서 바뀔 수 있다 — 지금은 계획이지 확정이 아니다.

## 왜 APK 패키징을 두 번 하는가
하드웨어 검증에서 브링업을 끝까지 미루지 않고 초기 샘플로 먼저 실기 검증하는 것과 같은 이유다. Phase 1이 끝나자마자 한 번 러프하게 APK로 감싸서 실제 폰에 설치해보면, "패키징 과정 자체에서 뭐가 깨지는지"를 초반에 발견할 수 있다. 이걸 Phase 2(디자인)까지 다 끝난 뒤에 처음 시도하면, 문제가 생겼을 때 원인이 기능 코드인지 디자인 코드인지 뒤섞여서 디버깅이 어려워진다.
